# 售后智能 Agent 平台 · 操作手册

> 本文面向**使用者与运维人员**，讲"怎么用"；不讲实现原理。
> 适用版本：含客户线索、转人工客服、飞书工单指令的版本。

---

## 1. 这个系统能做什么

用户用一句话说出需求，系统自动完成：

- **售后咨询**：从知识库检索政策、故障码排查方法，答不上来时**明确拒答并引导转人工**
- **报修建单**：识别设备型号与故障码，创建工单并**自动派给合适的工程师**
- **查订单 / 物流 / 工单**：按手机号或工单号查询
- **退款申请**：AI 初审 + 风控评分，低风险自动通过，其余转人工审批
- **转人工**：用户要求或系统判断需要时，建转人工工单并通知客服
- **客户线索**：识别合作 / 采购 / 报价意图，自动建线索并分配销售

## 2. 四种角色与权限

| 角色 | 中文 | 主要能做什么 |
|---|---|---|
| `admin` | 管理员 | 全部功能，含人员与系统配置 |
| `supervisor` | 主管 | 工单改派、退款审批、线索分配、查看审计 |
| `engineer` | 工程师 | 接单、拒单、开始处理、标记解决、关闭工单 |
| `agent` | 客服 | 转人工接管、线索跟进、客户建档、创建工单 |

**权限按操作细分**：能看工单不等于能接单，能接单不等于能改派。
权限在「人员管理」页面上可以按人单独放开或收回。

## 3. 飞书指令速查（最常用）

**使用方式**：在飞书里给机器人发消息。群里需要 **@业务助手**，私聊直接发。

**不确定能发什么时，先发 `命令`** —— 机器人会按你的角色列出全部可用指令。

### 3.1 查询类

| 指令 | 作用 |
|---|---|
| `命令` | 列出你能用的全部指令（按角色裁剪） |
| `我的工单` | 列出我手上进行中的工单，**并提示每条下一步能发什么指令** |
| `工单详情 <工单号>` | 查看某个工单的完整信息 |
| `工单 <工单号>` | 同上 |
| `催单 <工单号>` | 加急该工单，SLA 压缩到 2 小时内，并通知工程师与主管 |
| `加急 <工单号>` | 同上 |

### 3.2 处理工单类（工程师）

| 指令 | 作用 | 状态变化 |
|---|---|---|
| `接单 <工单号>` | 接下这个单 | 待接单 → 已接单 |
| `开始处理 <工单号>` | 开始干活 | 已接单 → 处理中 |
| `处理 <工单号>` | 同上（口语说法） | 已接单 → 处理中 |
| `解决 <工单号> [备注]` | 标记已解决 | 处理中 → 已解决 |
| `关闭 <工单号>` | 关闭工单 | 已解决 → 已关闭 |
| `拒单 <工单号> [原因]` | 拒单，系统自动重派给别人 | 回到待接单 |

**实例**：

```
接单 TBF792FD4
开始处理 TBF792FD4
解决 TBF792FD4 已更换主板
关闭 TBF792FD4
拒单 TBF792FD4 配件缺货，需客户等待
```

> ⚠️ **「处理」和「接单」不是一回事**：
> 「接单」是把这个单认领下来；「开始处理」才是进入"处理中"。
> 如果你已经接单了再发「接单」，会提示状态不允许流转 —— 这时应该发「开始处理」。

### 3.3 退款审批类（主管）

| 指令 | 作用 |
|---|---|
| `待审批` | 查看待审批的退款单列表 |
| `同意 <退款单号>` | 通过退款 |
| `驳回 <退款单号> [原因]` | 驳回退款 |

### 3.4 其他

| 指令 | 作用 |
|---|---|
| `转人工` | 需要人工客服时使用，会建转人工工单并通知客服 |

## 4. 飞书使用的常见问题

### 4.1 发消息没反应，或者回「未绑定系统用户」

**原因**：你的飞书账号还没和系统里的用户绑定。

**解决**：让管理员到「人员管理」页面，找到你的账号，用**「按手机号反查」**自动填入 open_id；
或者手动把 open_id 填进该账号的「飞书 open_id」字段。

### 4.2 私聊机器人时收到「access not configured」和一个配对码

**原因**：这是 OpenClaw 网关的**配对授权机制**，不是本系统的问题。
群聊不校验配对，**私聊**陌生账号会被拦下。

**解决**：把提示里的配对码发给机器人管理员，由管理员在服务器上执行：

```
openclaw pairing approve feishu <配对码>
```

批准一次即可永久生效。

### 4.3 转人工之后，每发一条消息机器人都回一句「正在为您服务」

**这是设计行为**：客服已接管，AI 会静默，避免和真人抢话。
你的消息已经推送到客服台，等客服回复即可。

### 4.4 提示「权限不足：角色「工程师」无权执行 xxx」

**原因**：你的角色没有这个操作的权限。

**解决**：发 `命令` 看看你的角色实际能做什么；确实需要更多权限时找管理员在「人员管理」里调整。

### 4.5 提示「工单信息不完整（缺: xxx），请先补全」

**原因**：报修建单时没给全设备型号或故障码，工单被标记为"待补充"。
**不完整的工单不允许进入"已接单 / 处理中"**，避免工程师拿着不清楚的单子干活。

**解决**：在管理后台的工单详情里点「补全信息」，或让用户在飞书里补充后重新触发。

## 5. 管理后台：工单管理

路径：左侧导航 →「售后业务」→「工单」

### 5.1 工单状态流转

```
待处理(pending) → 待接单(assigned) → 已接单(accepted)
   → 处理中(in_progress) → 已解决(resolved) → 已关闭(closed)
```

任何环节都可以**拒单(rejected)**，拒单后系统自动重派给其他工程师。

### 5.2 怎么操作一个工单

1. 在列表里筛选状态或搜索工单号
2. 点「查看」打开详情抽屉
3. 在详情底部的「🎬 可用操作」区，**只显示当前状态能做的动作**
4. 点按钮即可流转，成功后列表与详情会自动刷新

### 5.3 自动派单规则

创建工单时按三级排序选人：

1. **技能匹配** —— 工程师的技能集要覆盖该故障码或设备型号
2. **在线状态** —— 只派给在线的人
3. **负载升序** —— 手上的单越少越优先

拒单时会排除原工程师重新派。

### 5.4 SLA 时效

不同优先级有不同处理时限，后台**每 5 分钟扫描一次**：

- 接近超时 → 发**预警**给工程师
- 已超时 → 发**告警**给工程师和主管

## 6. 管理后台：客户线索

路径：左侧导航 →「销售与客服」→「线索管理」

### 6.1 线索的六个阶段

```
新建 → 已联系 → 已报价 → 谈判中 → 已成交 / 已流失
```

- 阶段**不能随意跳**：新建不能直接到已成交，必须先"已联系"
- 标记**已流失必须填写原因**
- 已流失的线索可以**重新激活**回"已联系"

### 6.2 谁负责跟进

每条线索都有**负责人**。

- 新建线索时**不填负责人** → 系统自动分配
- 自动分配规则：**销售岗位优先** → 进行中线索数最少 → 编号靠前
- 手动指定负责人需要 `lead.assign` 权限

### 6.3 进度自动留痕

**每次阶段变化、报价变化、成交，系统都会自动写一条跟进记录**，不需要手工补记。
在详情抽屉的「跟进时间线」里可以看到完整历史，例如：

```
线索创建，自动分配给 小林
阶段：新建 → 已联系
报价：0 → 80000 元
阶段：已联系 → 已成交
```

### 6.4 AI 自动捕获线索

用户在飞书里表达**合作 / 采购 / 报价 / 代理 / 加盟**等意图时，系统会自动：

1. 从原话里提取**手机号**和**公司名**
2. 建一条线索（来源标记为"飞书咨询"）
3. 自动分配给销售
4. 回复用户线索编号与对接人

同一个会话**不会重复建线索**（已有一条未结束的线索时会复用）。

### 6.5 漏斗统计

页面顶部显示：总线索数、进行中、已成交、成交率，以及报价总额、成交总额、平均成交额。

## 7. 管理后台：人工客服台

路径：左侧导航 →「销售与客服」→「人工客服台」

### 7.1 转人工是怎么发生的

以下任一情况会创建转人工工单（状态 `待接入`）：

- 用户在飞书里说「转人工」
- 用户投诉
- 业务规则判定需要人工处理

同时系统会**私聊通知客服与主管**，并广播到客服群（需配置群 webhook）。

### 7.2 接管的完整流程

1. 工单出现在客服台左栏「待接入」
2. 点开某条 → 中间显示完整会话（包含接管前的 AI 对话）
3. 点【认领】→ 状态变为「已接管」，**用户会收到"客服已接入"的提示**
4. 在底部回复框输入内容，`Ctrl+Enter` 发送 → 用户飞书收到
5. 处理完点【结束接管】→ 填结单说明 → 用户收到"已转回智能助手"

### 7.3 接管期间 AI 会自动静默

坐席**认领之后**，该会话的用户消息**不会再触发 AI**，只推送到客服台。
这是为了避免 AI 和真人同时回复、互相抢话。

### 7.4 超时会自动处理

| 情况 | 系统行为 |
|---|---|
| 待接入超过 **5 分钟**无人认领 | 标记超时，**升级通知主管**，并告知用户"已记录，会尽快联系" |
| 已接管但 **4 小时**没有任何新消息 | **自动结束接管并转回 AI**，避免会话被永久静音 |

> 第二条是兜底：坐席如果忘了点「结束接管」，这个会话会一直静默下去，用户发什么都没反应。

### 7.5 顶部统计

待接入 / 已接管 / 已结束 / 已超时 / 平均响应时长，以及按坐席的处理量排行。

## 8. 管理后台：知识库

路径：左侧导航 →「知识库」

- **上传文档**：支持 PDF / Word / Excel / Markdown / 纯文本
- **知识库统计**：查看已入库的切片数量
- **快速检索测试**：输入问题，看命中了哪些片段、相似度多少
- **已入库文档列表**：可查看某篇文档的父块与子块切分结果

**检索策略**：关键词（BM25）与向量**双路召回**，融合后重排取最相关的几段。
**答不上来时会明确拒答**，引导用户转人工，而不是编一个答案。

## 9. 管理后台：人员与权限

路径：左侧导航 →「组织与人员」→「人员管理」

### 9.1 新建人员

必须设置初始密码（至少 6 位），否则该账号无法登录管理后台。
创建后请把初始密码告知本人，并提醒他登录后立即修改。

### 9.2 绑定飞书

要让一个人能通过飞书操作（收到通知、执行指令），必须绑定他的飞书 `open_id`：

- **推荐**：点「按手机号反查」，系统自动填入
- 手动填：把 `ou_` 开头的字符串填进「飞书 open_id」字段

**没绑定的人收不到任何飞书通知**，也无法使用飞书工单指令。

### 9.3 权限调整

- 角色决定默认权限（见第 2 节）
- 还可以**按人单独放开或收回**某些权限
- 权限变更**立即生效**，不需要当事人重新登录

### 9.4 改密码会让旧登录失效

用户修改密码、或被管理员重置密码后，他此前所有的登录状态**立即失效**，需要重新登录。

## 10. 管理后台：退款审批与 SLA

### 10.1 退款审批

路径：「售后业务」→「审批台」

- 低风险、低金额的退款由 AI 自动通过并执行
- 其余转入人工审批，显示在「待审批退款」
- 主管可**批量通过**
- 审批结果会通知客户与相关客服

### 10.2 SLA 时效

路径：「售后业务」→「SLA 时效」

- 查看各状态的工单数量与预警 / 超时情况
- 可手动触发一次扫描
- SLA 规则（时限、通知对象）可按优先级配置

## 11. 运维与排障

### 11.1 服务健康检查

```
curl http://127.0.0.1:18001/health
```

返回 `status: ok` 即为正常。

> 返回里 `openclaw.reachable` 为 `false` 属于**正常现象** —— 我们的后端探不到网关
> （网关只监听回环地址），但真正的业务方向是「网关 → 后端」，是通的，不影响功能。

### 11.2 创建工单后工程师没收到飞书通知

按顺序排查：

1. 该工程师账号是否绑定了 `feishu_open_id`
2. 服务是否配置了飞书应用凭据（`FEISHU_APP_ID` / `FEISHU_APP_SECRET`）
3. 查看「通知记录」页面里这条通知的状态与错误信息

### 11.3 飞书里发消息完全没反应

1. 群里是否 **@了机器人**
2. 看网关日志是否收到消息
3. 确认后端服务在运行

### 11.4 客户线索的负责人被分给了管理员

说明**销售池里没有岗位名称含"销售"的人**。
自动分配会优先选销售岗，如果没有销售岗，才退化为全体有线索编辑权限的人。
给销售账号把「岗位」设成"销售"即可。

### 11.5 容器内存与日志

```
docker stats --no-stream
docker compose -f docker-compose.prod.yml logs app --tail 50
```
